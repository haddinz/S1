============================================================== % DB Relation % ====================================================================

Dalam pembuatan relasion antar models database.
Sebenarnya dari models sendiri sudah dapat dibaca dengan hanya mengandalkan

// Models Example
public DbSet<Example> Examples {get; set;}

Hanya saja terkadang kita butuh yang lebih explisit dengan menggunakan model builder
Perhatikan relasionnya onetomany atau manytoone

modelBuilder
.Entity<Platform>() // FOKUS pada Platform (Sisi "One")
.HasMany(p => p.Commands) // Ia memiliki BANYAK Commands
.WithOne(p => p.Platform) // Setiap Command terhubung ke SATU Platform
.HasForeignKey(p => p.PlatformId); // Hubungan itu menggunakan kolom PlatformId

modelBuilder
.Entity<Commands>() // FOKUS pada Commands (Sisi "Many")
.HasOne(c => c.Platform) // Setiap Command terhubung ke SATU Platform
.WithMany(c => c.Commands) // Platform tersebut (yang satu itu) memiliki BANYAK Commands
.HasForeignKey(c => c.PlatformId); // Hubungan itu menggunakan kolom PlatformId

Jika One-to-Many maka pada models wajib ada =

- relasi one Platform
  public ICollection<Commands> Commands = new List<Commands>();

- relasi many Commands
  public Guid PlatformId {get; set;}
  public Platform? Platform {get; set;}

satu Platform punya banyak Commands

Lazi Initialisasi sebuah design system yang membuat object yang kita buat akan masuk kememory hanya saat kita berikan action.
Karna pada dasarnya ketika object dibuat ia akan secara otomatis akan dimasukan ke memory ketika first render / load.
(sudah dihandle dengan AddScope<>)

Lazy Initialisasi seperti yang kau temui tidak semua skenarion cocok menggunakan itu.

Hindari jika method tersebut merupakan:

- Long-Lived Resources ,jaringan TCP (dibuat sekali dan digunakan kembali)
- Objek yang Membutuhkan Pembuangan (IDisposable Berat)
- Skenario Multi-Threading dengan Status Bersama (Race Conditions)
  Jika beberapa thread mungkin mencoba mengakses dan menginisialisasi
  objek lazy secara bersamaan, Anda berisiko mengalami race condition
  jika tidak dilindungi dengan benar
  (misalnya, menggunakan lock atau Lazy<T>).

Ingat perbedaan

- AddScope<>() = Jika service sering dipakai dan perlu operasi baru setiap kali direquest
- AddSingleton<>() = connection, message broker, TCP atau object yang mahal untuk dibuat dan harus sekali
- HostedService Backgroud Service

============================================================== % Exception Level and Try Catch % ====================================================================

=>  Penggunaan exception middleware harus dibedakan mana untuk user dan mana untuk developer.
    Bagusnya exception ang masuk ke middleware jika ditujukan ke user menggunakan status code selain 500.
    ( 500 Internal Server Error ) error khusus dev.

=>  Sebaiknya jika menggunakan efcore direpo tidak perlu menggunakan throw exception
    Akan redudent dan DRY (dont repeat your self), karna sudah dihandle oleh efcore nya

=>  Level trycatch untuk buang throw exception baiknya diatur pada midleware serta di inject di root(program)


Try-Catch layak digunakan ketika:

External Resource Recovery
- Jika ingin menggunakan exception trycatch diservice, lebih baik pada scenario
  getting data from db. If chace null then catch from db. Karena ada fallback
  try
    return await redis.GetAsync(key);
  catch
    return await database.GetAsync(key);

File Stream
- Jika ingin menggunakan exception trycatch di controller,  lebih baik pada scenario
  getting or putting or patching some file stream scenario. Karena ada handling khusus.
  try
    using FileStream ...
  catch(IOException)

Third Party API
- Karena ada recovery strategy.
  try
    await paymentGateway.PayAsync();
  catch(HttpRequestException)

==> Kolom Spesifik SELECT KolomA, KolomB ==>            ||      .Select(x => new { x.KolomA, x.KolomB })
          
==> Filter WHERE Kondisi ==>                            ||      .Where(x => x.Kondisi)
          
==> Relasi (Join)LEFT JOIN TabelB ON  ==>               ||      ....Include(x => x.TabelB)
          
==> Relasi Beruntun LEFT JOIN B ... LEFT JOIN C ==>     ||      ....Include(x => x.B).ThenInclude(b => b.C)
          
==> Urut Data ORDER BY Kolom ASC ==>                    ||      .OrderBy(x => x.Kolom)
         
==> Urut Terbalik ORDER BY Kolom DESC  ==>              ||      .OrderByDescending(x => x.Kolom)
          
==> Batasi DataLIMIT 1 atau TOP 1 ==>                   ||      .FirstOrDefault() atau .SingleOrDefault()
         
==> Agregasi COUNT(*), SUM(), AVG() ==>                 ||      .Count(), .Sum(), .Average()
